## 修复的用户流程阻塞

此前“环境/认证”页只能浏览环境列表，却没有任何创建环境的 Web
入口；新增表单认证又必须依赖一个先前存在的环境，刚创建项目的
负责人无法靠 Web 完成首次配置。

本阶段已交付：

1. **新增环境表单**：环境名称、完整 Base URL（保留 path/query）、
   HTTP(S) 获准 Origins、排除路径和 TLS 证书策略。
2. **从 Base URL 辅助填充 Origin**，但不暗中扩大范围；
   Base URL 的 origin 必须在用户批准范围内。Origin 字段拒绝
   嵌入账号/密码、路径、查询参数、非 HTTP(S) 协议。
3. **自签名证书需单独确认**；不允许借选择器默默将 HTTPS
   严格验证降级。允许自签名仅限用户确认的 HTTPS 测试环境。
4. **服务端成功后展示环境**；若此前没有可用环境，创建的环境
   自动成为认证档案可选的关联环境，Origins 同步自环境授权。
5. **认证配置加入 none 模式**，可明确创建不含账号/密钥的
   匿名认证档案；原有 form/storage_state 和成功判定表单保留，
   含密钥档案继续 write-only，不在表格回显真实凭据。
6. 首页项目环境列表加载后自动选中首个环境，Base URL 成为
   默认待测 URL，保留路径和查询参数；更换环境同时清除旧
   认证选择以避免混用；认证下拉框仅显示当前环境或通用档案。
7. 项目负责人/管理员可写；其他项目成员只读。真正权限由
   PostgreSQL / repository `config.write` 规则执行，页面隐藏表单
   并不代替服务器授权。

## 服务端权限补齐

`ConfigurationRepository.createAuthProfile` 现基于项目和
`environmentId` 读取拥有权限的环境版本。如果档案关联环境，
所有 `allowedOrigins` 必须在该环境的 Origin 集合中；其他
项目环境被拒绝。先校验范围和权限，再写入加密凭据。非法
操作使用现有 `TARGET_NOT_ALLOWED` / `NOT_FOUND` 错误码。
