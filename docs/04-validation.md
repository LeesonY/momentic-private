# 验收、fixture 与故障测试方案

此文件是后续开发的验证计划。当前只完成需求/契约工作，没有运行 LocalQA、Linux Worker、真实模型或业务网站测试。

## 1. 验证层次及交付门槛

| Gate | 验证内容 | 不能据此证明的内容 |
| --- | --- | --- |
| G0 文档/契约 | JSON Schema、OpenAPI refs、枚举、样例、统计和引用一致 | 不证明应用已实现 |
| G1 领域/组件 | 状态、权限、预算、策略、去重、model adapter、材料和恢复 | mock 不证明真实模型效果 |
| G2 真浏览器闭环 | 受控 fixture、真实 Playwright、DB/队列/SSE/材料；可用固定模型 stub | 不证明自由探索准确性 |
| G3 选定模型 | 同一 fixture 使用真实模型执行和独立复现，记录精度、成本、版本和失败 | 不证明所有业务都适用 |
| G4 Linux 多用户/运维 | Compose、沙箱、权限、配额、故障、取消、备份恢复和性能 | 不证明集群或原生移动端 |
| G5 用户业务试点 | 经授权目标与账号，先非提交冒烟，遵守数据约定和基线 | 有限范围通过不能写成全站通过 |

M0 需要 G0/G1 关键项、G2 核心和 G3 最小样本；P0 release 需要 G0–G4 的全部 P0 项。环境/模型缺失时明确部分完成，不用 stub 成绩填充空缺。

## 2. 必须建设的受控 fixture

fixture 是本项目创建的内部网站，生产默认不启用。提供 reset、seed、只读 audit、预设故障和角色账号；数据带 `LQA_<runId>_<caseId>`，不连接既有业务数据库或真实收件人。

| FIX | 场景 | Oracle/证据 |
| --- | --- | --- |
| FIX-01 | 首页、main 内容、导航、tab、折叠、分页 | 固定可见节点、路径、内容和请求 |
| FIX-02 | 延迟渲染、spinner、长期连接 | 状态等待可完成，不依赖 networkidle |
| FIX-03 | 登录、状态复用、失效 session | 固定成功节点、cookie 隔离；认证失败保持受阻 |
| FIX-04 | viewer/admin 功能差异 | 显式角色规则；隐藏管理功能不自动提 Bug |
| FIX-05 | 重复文字、隐藏按钮、DOM 重排 | 不误点；过期 snapshot 拒绝；同语义重定位 |
| FIX-06 | 同域/获准跨域 iframe、popup | frame/page IDs、范围检查和缺口 |
| FIX-07 | 外域跳转、危险 GET、自动保存、删除/发送 | 未授权动作不发生，audit 为 0；不全局阻断 POST |
| FIX-08 | canvas、模型无图片能力 | 不支持时准确标明未验证 |
| FIX-09 | 断链、500、空白、按钮无响应 | 固定条件失败与独立复现 |
| FIX-10 | 错误金额/权限、有/无业务规则 | 有规则时检测，无规则时不伪造预期或通过 |
| FIX-11 | 一次性与稳定故障 | 初见不直接 confirmed；未复现保持 unconfirmed |
| FIX-12 | secret、token query、console/network 哨兵 | 出网、SSE、日志、报告、截图/ZIP 脱敏 |
| FIX-13 | 错误/恶意工具、假证据 ID、越界路径 | Schema/policy 拒绝，无任意代码执行 |
| FIX-14 | 大页面、回放/下载超限、磁盘满 | 明确限额/degraded，材料缺失影响判定 |

模型 stub 可确定地产生正常、格式错误、不支持图片、超时、429、重复动作、假证据和未授权工具。真实模型样本另跑并分别报告。

## 4. 真实模型质量基线

固定模型、adapter、prompt、浏览器版本，10 条健康流程各独立执行 10 次，至少 100 个首次结果。另选 10 个明确 in-scope 的预设错误各独立检查至少 3 次；每次 reset/seed，人工核对 oracle。

建议 P0 试点门槛（目标而非成绩）：

- 健康流程首次完整通过率 ≥95%，重试后通过单列。
- 已执行的指定错误检查无错误通过；未检查错误在未运行/覆盖缺口中出现。
- ≥90% 指定 in-scope 错误有有效失败/问题记录；遗漏样本逐项解释。
- confirmed 功能问题满足相同 oracle，且有全新复现证据。
- blocked/inconclusive、中文/iframe/canvas 等场景分别记录原因。
- 时延、tokens、请求数和成本区分 reported/estimated；缺少用量不填零。

小样本不能证明生产风险为零。模型/prompt/截图/浏览器/缓存变化后重跑受影响样本，不无限重复未受影响的检查。

## 5. 故障与一致性

| 故障点 | 预期 |
| --- | --- |
| Run 创建后响应丢失 | Idempotency-Key 返回同 run，无第二套任务 |
| 协调器建子任务时重启 | 唯一键防重复，阶段从 DB 恢复 |
| 操作前/后/提交前崩溃 | 区分未开始/unknown，不重放未知副作用 |
| 过期 Worker 返回 | 不提交权威结果，可保留有限审计 |
| 模型超时/取消后晚返回 | 无后续动作，用量保守记录，终态不改变 |
| NOTIFY 丢失 | 轮询补偿，不丢任务/事件 |
| SSE 断线/重复/过期 | seq 恢复/去重，必要时状态快照，不重启运行 |
| 认证/模型密钥撤销 | 不匿名/未知 fallback，停止或受阻 |
| 磁盘满/材料超限 | 显式拒绝/降级，不能伪造 available |
| DB 重启 | 恢复已提交数据，未提交动作按 intent 处理 |
| 无效 cron/时区/重叠（P1） | 验证、occurrence 去重和明确重叠政策 |

## 6. 多用户、性能与部署

参考 16 vCPU/32 GiB/SSD Linux、4 槽位、10 在线用户；报告硬件、内核、容器、字体、网络、模型。不得暗中更换硬件后沿用旧成绩。

测首页、历史/用例/任务分页、1 万事件、SSE 多连接、Range 下载、排队与公平性。非长任务 API P95≤500 ms、事件提交至 UI P95≤2 s；模型/被测站时延单列。

验证非 root Chromium/sandbox、共享内存、PIDs/内存、内网 DNS、CA/TLS 策略、代理、范围和隐藏内部入口。容器启动不等于浏览器能力通过。

备份恢复演练：新数据卷恢复 DB、材料和独立 KEK，读取报告/授权材料，正确解密认证；旧 lease 不视为活动任务。迁移失败和回滚策略记录实测结果。

## 7. 验收交付材料

每 Gate 提交代码/镜像/契约版本、命令、环境、模型配置、fixture seed、样本量、结果列表、必要证据、失败解释、未验证项及清理回查。

只清理自建临时数据/scratch；修改 fixture 既有数据前记录基线。保留开发证据与复现材料。release 报告区分真实运行、stub、外部阻塞。
