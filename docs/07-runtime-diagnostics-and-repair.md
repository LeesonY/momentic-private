# 执行诊断、保守修复候选和连续业务流程：当前边界

本文件说明 2026-10-13 这轮 Web 端增量能力，**不是** P0 放行或生产验收报告。
移动端测试不在当前计划内。

## 真实执行与诊断

- 浏览器画面来自 Worker 实际采集的截图和步骤，**不是实时视频**。页面只展示已收到的真实状态，不以 Mock/未收到的状态填充通过结果。
- 步骤接口在数据库侧分页；前端按游标读取，限制每轮加载 20 页、每页最多 100 条，防止长运行轮询无界增长。未加载的剩余步骤会明确提示。
- 每条步骤可展开查看当前结果、结束时间、冻结回归来源及证据数量。截图仍须通过已有工件权限、保留期和脱敏规则。
- SSE 使用有序序号及重连机制，历史和实时事件的每次数据库读取限额 200 条，直播轮询串行且有界；响应断开时清理定时器。787 条历史/突发事件的模拟序号测试无丢失、重复。不要将“连接中”或“等待截图”解释为通过；真实环境仍需联调验收。

## 失败恢复

- 固定回归的点击和输入**只在执行前**可因 `LOCATOR_NOT_FOUND` 或唯一实时元素未被当前快照拥有的 `LOCATOR_SNAPSHOT_STALE` 进行最多 3 次新观察与定位。发现多个拥有目标时仍直接失败。每次重新读取当前 DOM 和当前快照身份，且经过原动作授权与预算路径。
- 已派发动作的成功、失败或未知副作用**不重放**；遇到歧义定位、认证错误、策略拒绝、取消、额度不足以及断言失败立即停止。
- 回归记录包含 `resolutionAttempts` 与 `recoveryCodes`，供追责与审计使用。
- 页面循环检测依据语义控件结构的本地哈希，不再仅比较 URL、标题和节点总数；真正重复的操作仍会被限制。

## 自动维护建议（不等于自动改写）

- Worker 仅在冻结回归步骤因 `LOCATOR_NOT_FOUND` 失败时，对真实、脱敏、非截断的快照计算定位候选。当前只支持在**单一、主框架、可见、启用、非敏感**节点上证明的名称大小写/空白变化；不猜测业务语义，也不跨框架重定位。
- 输出 `repairSuggestions` 仅进入当前回归任务的结果，包含批准来源、失败定位器、建议定位器、快照、失败原因及 `reviewRequired=true`、`verification=not_run`。输出无原始查询参数、输入值或密码。
- `listRepairProposals` 读取端只返回**同项目、同保存用例、同执行任务的不可变回归绑定、已批准来源版本及一致源文档哈希**的最多 10 条有效建议；还要求回归实际以 `LOCATOR_NOT_FOUND` 失败。无效旧记录忽略。页面与正式 `RepairProposal` 分离显示，不允许一键替换正式基线。
- 正式修复提案仍须符合原有“已确认、独立复现的产品问题”权限规则。定位漂移可能只是测试维护问题，不得伪造 confirmed Finding 以绕过审批。建议候选不得自动调用高风险动作。
- 当前候选算法是确定性的 DOM 语义匹配，不是完整 LLM 推理的自愈 Agent。后续需要独立验证提案、更广泛的模型辅助候选、证据对比及审核后发布工作流。
- 2026-10-13 本轮后续增量：Web 用例详情现在可将同一已批准基线版本的执行器定位建议转换为**最小定位器变更的完整 RegressionDocument 预览**，显示修改前后及完整 JSON。仅在操作者明确确认后调用已有版本 API 创建**待审核草稿**；原始准则、断言、步骤顺序和变量不允许自动修改。模块内步骤、其他版本、不同源页面、歧义或非等价定位均拒绝自动生成。草稿不自动验证、不自动批准、更不自动更新基线；独立验证与完整维护闭环仍未完成。
- 执行画面增加已读取步骤数、失败/运行中数量、最近截图采集时间以及人工回放后的“跟随最新画面”入口；截图仍不等于实时视频。
- T49 Web 增量：工作台把现有、经项目权限校验的 `step.recorded` SSE 事件按 runId+taskId 定位到画面组件，触发尾部分页重读；事件仅作失效通知，**不携带图片 URL、图片数据或通过结论**。短时间事件合并为单次刷新，每个可见画面最多约每 500ms 启动一次读取、请求串行且尾随补齐，原有 2.5 秒轮询仍作为丢事件/断线兜底；切换任务时取消定时更新和清理上一个任务的游标。当前是**事件驱动的近实时步骤截图**，不是连续视频、远程浏览器控制或自定义截图通道；敏感内容继续走现有授权工件和脱敏校验。
- 独立 Chromium 候选验证器现与固定回归共享**同一安全重观察原则**：仅在浏览器动作前允许最多 3 次定位，因 `LOCATOR_NOT_FOUND` 或 `LOCATOR_SNAPSHOT_STALE` 更新快照；歧义定位、取消、策略拒绝立即失败，不重复派发已执行的浏览器动作。这强化的是原有正式修复候选验证器，并**未**给普通定位维护草稿赋予产品缺陷审批权限。
- T47：普通定位漂移现在有**独立的维护来源记录**（`locator_maintenance_drafts`），无需伪装成确认的产品 Bug。服务端从冻结的 `run_case_regression_bindings`、确切失败任务和当前已批准用例计算一个最小定位器修订，拒绝客户端任意自选源和修改业务断言。每个维护版本可排入独立、无凭据、非提交模式的 Chromium 验证队列，与缺陷候选共享租约、隔离浏览器和加密证据，但是任务关联身份强制互斥。验证状态、断言步骤、脱敏截图仅按授权查看。PostgreSQL 审核触发器拒绝任何尚未取得**同一版本 SHA-256**、已成功且有真实截图断言证据的维护草稿审批；原有负责人两阶段审核仍适用，批准不等于自动回放下一次生产环境。当前只支持单一 origin、≤30 个非提交步骤、无模块和固定可验证断言；跨域登录/表单提交、多模型自愈和视频并未覆盖。
